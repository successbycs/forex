# Goal prompts

This directory retains proposed wave prompts and historical human-approved
Goal Mode prompts. Each document states its status; saving a prompt does not
authorise its execution. A goal prompt is an execution brief, not evidence of completion;
the milestone registry remains the declarative contract and `project_state`
remains the mutable execution record.

| --- | --- |

| [Demo income wave guide](demo-income-waves.md) | Proposed three-wave sequence, shared boundaries, operator decisions, and usage controls. |
| [Wave 1: Trustworthy Demo execution](demo-income-wave-1.md) | Copy-and-paste goal for lifecycle correctness, accounting, and persistent risk controls. |
| [W1.R: T480 reliability and recovery work package](demo-income-wave-1-recovery-work-package.md) | Proposed R1–R7 fix schedule, owners, dependencies, success criteria, real-world tests and rollback boundaries; not executed. |
| [Resume Wave 1: 25,000-token brief](demo-income-wave-1-resume-goal.md) | Reviewed continuation prompt that preserves completed work and prioritises current T480 liveness findings. |
| [Wave 2: Consistent, cost-aware decisions](demo-income-wave-2.md) | Copy-and-paste goal for entry eligibility and parity between replay and execution. |
| [Wave 3: Economic evaluation and operational proof](demo-income-wave-3.md) | Copy-and-paste goal for a frozen experiment, low-maintenance operation, and evidence-based review. |
| [Research-based trading wave](research-trading-wave-goal.md) | Proposed R0/E1-E5 goal with frozen shadow hypotheses, complete economics and T480 continuity tests; not an automatic next wave. |

Keep prompts versioned with the related architecture decision. Never put
credentials, account details, database passwords, or broker secrets in them.
