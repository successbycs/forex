# M33.3 independent investor observer

## Decision

Preserve the full M33-C7 missing-terminal branch by using a separate MT5
investor-password observer. MetaTrader 5 documents investor authorisation as
account-status access without trading rights: [official MT5 help](https://www.metatrader5.com/en/terminal/help/startworking/authorization).

## Boundaries

The observer is a separate `CS AI Lab MT5 Observer` Session-0 S4U task and a
separate MT5 data directory. Its investor credential is a Windows-protected
secret and must never be committed, staged in a payload, logged, or placed in
a local JSON record. The observer is not a managed recovery target; it cannot
be stopped by duplicate cleanup and it is never counted as the execution
terminal. A broker-native read-only API was considered but no GOMarkets
adapter, credential or contract exists in the current runtime.

## Two-phase evidence

1. Capture the existing managed task/process candidate read-only on T480.
2. Under separate held authority, provision the observer task, protected
   credential and hash-bound observer binding. Run a no-order snapshot that
   proves Demo/AUD/EURUSD, no positions, no pending orders, no unresolved work
   and `STRUCTURALLY_UNAVAILABLE` order submission.
3. Only a fresh (30-second) binding-matched observer witness may unlock the
   *precondition* for `START_ONE_MT5`. The start effect remains separately
   reviewed and fixed; the hold stays on and entry remains false.

## Local contract

`trading_health_managed_mt5_recovery_executor.py` validates the observer
binding and witness before it moves from an absent-terminal refusal to the
separate fixed-effect gate. This local implementation does not create a task,
credential, observer process, MT5 connection or order authority.
